# 元素准确性标准（项目模板 · v1.0 · 2026-10-16）

> 本文档把「元素数字必须准确」沉淀为**可复用的项目标准**。以后凡是基于元素统计做
> 选路 / 排班 / 报告的项目，按此标准执行；本仓库（惠城区 ODD 排班）即首个实例。
> 配套断言已固化在 `audit_data.js` K 段与 `tools/audit_all_elements.js`，**改口径必须同步改这里**。

## 0. 一句话原则

**同一个数，全链只许一个值；对不上的差异必须分类说明（预期内 / 真不一致），不许静默存在。**

---

## 1. 数据契约：一个元素类，五个口径字段

每个元素类的数量沿一条**单向管道**加工，每一站落一个字段，缺一不可、顺序不可换：

```
raw ──载体过滤──> afterCarrier ──去重合并──> afterDedupe ──区内归属──> inArea
```

| 字段 | 含义 | 规则 |
|---|---|---|
| `raw` | 源数据原始条数 | OSM elements / 高德 POI 原样计数，不做任何加工 |
| `afterCarrier` | 剔除非 ODD 载体后 | **修饰符型元素**（OSM `tunnel=yes` / `bridge=yes` 这类挂在别的地物上的标签）必须过 `lib_carrier_filter.js` 的 `carrierCheck`：铁路隧道、水道涵洞、人行步道不是 ODD 载体，剔除并留 `droppedDetail` |
| `afterDedupe` | 同实体去重后 | 同一构造物被切成多段 / 同一道口标多个节点 → 按半径聚类合并（构造物 50m、道口 50m），合并数落 `dedupeMerged` |
| `inArea` | 区内真实存量 | 坐标先**纠偏**（POI 是 GCJ-02 必须转 WGS-84）再按**街道多边形**归属；落不进 18 街道的记区外，不进区内数 |
| （配额面）`matched` | 落在可排班工作面上的 | `inArea` 里距命名道路 ≤80m 的；**配额 ≤ matched** 是硬约束（不许印出排班到不了的数） |

**权威定义**：`inArea` 由独立体检工具（`tools/audit_all_elements.js`）按上述管道**从 data/ 原始文件重算**，
各产物（统计层 / 配额层 / 选路层）只许引用或对齐，不许自造第二个值。

## 2. 三层对账（谁和谁必须相等）

| 层 | 产物 | 对账规则 |
|---|---|---|
| 统计层 | `out/street_stats.json` | 24 类静态元素：`Σ街道[k] == 配额层.districtTotal == 体检.inArea` |
| 配额层 | `out/odd_quota_roads.json` | 28 类：`districtTotal == 体检.inArea` |
| 选路层 | `out/odd_selection.json` | **默认** `kindCoverage.total == 体检.inArea`；例外见 §3 |
| 页面层 | 4 个交付页 | B 表 / ODD 表里每个类别的区内数 == `体检.inArea`（audit 逐类扫页） |

**审计断言（audit_data.js K 段）**：
1. `element_calibration.mismatches.length == 0`（真不一致 = 0）；
2. `expectedDiff.length == 6` **恰好**（不多 = 口径没漂移；不少 = 没把预期差异藏起来）；
3. 交付页隧道/桥梁必须写**载体校正后**的 隧道 79 / 桥梁 373（双页核对）；
4. 配额 ≤ 可排班面，28 类逐类。

## 3. 预期内差异（白名单 —— 只许这 6 条，逐条有据）

新增预期差异**必须**在本节登记理由，否则视为口径漂移：

| 类 | 差异 | 理由 | 兜底 |
|---|---|---|---|
| 立交桥 / 人行天桥 / 高速出入口 / 停止线 | street_stats 计 0 | 这 4 类是 **ODD 工况类**，刻意不进街道元素分布表（停止线 9,390 条会把「各街道元素密度」排名整个带偏） | 配额层仍有值且与体检一致 |
| 隧道 | select_odd 自报 315（过滤前区内） | 选路侧**刻意**不过滤载体：过滤会改元素计数 → 改配额 → 改选中道路集合（实测 165→164 条），导致已抓的高德路线全量作废 | 报告层由 `carrier_report` **只读校正**为 79，且 `rawTotalBeforeCarrier` 留痕 315 |
| 桥梁 | select_odd 自报 1,456（过滤前区内） | 同上 | 同上，校正为 373 |

⚠️ **兜底的兜底**：载体校正是「报告显示层」的补丁，若未来重抓路线（routes.json 重建），
应把载体过滤**前移进 select_odd**，届时删除这两条白名单（`select_odd` 与其余各层自然对齐）。

## 4. 准确性的两类证明（缺一不可）

1. **对账证明（链内）**：`tools/audit_all_elements.js` 独立重算 vs 三产物自报 → 0 真不一致。
2. **溯源证明（链外）**：抽样直接数原始文件（如 `data/signals.json` 1,601 条、`amap_schools` 700 条），
   与体检 `raw` 一致 → 证明体检没有自带偏差。抽样复核记录在体检输出里。

## 5. 坐标准确性（别让 POI 挪到隔壁街道）

- 高德 POI 坐标是 **GCJ-02**；区内归属前必须 `gcj2wgs` 纠偏（`out/coord_audit.json` 记录偏移量，
  实测 ≈ 东 500m 级 —— 不纠偏会把 POI 挪到隔壁街道）。
- OSM 数据天然 WGS-84，不纠偏。
- 断言：`coord_audit.rows[*].insideNoStreet == 0`（区内点必须有街道归属）。

## 6. 生成链位置（改口径后按序重跑）

```
（原始数据不动）
→ tools/audit_all_elements.js   元素体检（权威 inArea + 对账）
→ tools/build_carrier_report.js 载体校正（隧道/桥梁 79/373 + reachable/covered）
→ build_stats.js / build_odd_quota.js / select_odd.js   （引用对齐）
→ 4 个交付页 → audit_data.js（K 段最终把关）
```

## 7. 历史教训（为什么每条规则都存在）

| 教训 | 落成的规则 |
|---|---|
| 隧道 514 → 79、桥梁 2,370 → 373（铁路/水道/步道混入）| §1 载体过滤 + `droppedDetail` 留痕 |
| 同一道口标多个节点（最近邻中位 5.2m）被当多处工况 | §1 去重合并 |
| 体检把 6 条预期差异一锅端当「不一致」 | §3 白名单 + 分类（真失败 vs 有据差异） |
| 隧道/桥梁 select_odd 315/1456 与统计层 79/373 并存 | §3 载体校正闭环 + 页面断言写 79/373 |
| 静态元素集与 ODD 工况集混统计，密度排名被停止线带偏 | §3 4 类 N/A |
| 坐标不纠偏，POI 归错街道 | §5 |
| 期望值写死在审计里，上游改了审计还是绿的 | K 段期望值全部动态取自源文件 |
