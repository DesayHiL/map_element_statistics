# 工程分域说明

当前工程实际上包含四类能力。主链仍保持根目录脚本兼容，先用文档分域，避免直接移动脚本导致相对路径失效。

## 1. ODD 覆盖与交付主链（必须可离线复跑）

取数、归属、配额、选路、报告和终审：

`fetch_osm.js`、`fetch_amap_*.js`、`fetch_congestion.js`、`fetch_routes.js`、`fetch_kuandeng_stoplines.js`、`build_stats.js`、`plan_routes_v2.js`、`plan_scenario_routes_v2.js`、`select_odd.js`、`build_report_alloc.js`、`build_odd_*.js`、`build_scenario_html.js`、`build_weather.js`、`audit_data.js`。旧的 `report_draft.html` / `report_brief.html` 已停用，不再生成。

共享定义/库：`street_areas.js`、`scenarios.js`、`lib_*.js`、`tencent_route_link.js`、`chartjs.min.js`。

## 2. 宽凳域（路网约束与覆盖）

宽凳数据读取、路网覆盖、停止线和路线几何校验：

`lib_kuandeng.js`、`lib_kd_cover.js`、`fetch_kuandeng_stoplines.js`、`build_kuandeng_markings.js`、`check_stopline_signal.js`，以及 `out/routes_kd.json`、`out/route_kuandeng_routes.json`、`out/route_kuandeng_routes.html` 等产物。

## 3. 外部路线与环境数据域（高德/腾讯/天气交通/信号）

高德/腾讯路径、拥堵和信号覆盖属于外部数据增强，不应与 ODD 报告主链混称：

`fetch_routes.js`、`fetch_amap_*.js`、`tencent_route_link.js`、`fetch_congestion.js`、`build_congestion*.js`、`build_signal_heatmap.js`、`build_official_5g_map.js`。

信号页面仍保留在 `out/signal_coverage.html`（蜂窝热力）和 `out/official_5g_coverage.html`（电信/联通官方 5G）。天气查询不是独立服务，而是在生成 `out/odd_coverage.html` 时调用高德天气 API，写入“W · 惠城区 4 日天气预报”章节；接口失败时页面降级为提示，不阻断报告生成。

## 4. 平台/UAT 路线创建域（独立运维工具）

`uat_*`、`prod_*`、平台路线/站点缓存、截图和浏览器探查文件服务于平台操作验证，不参与四个正式交付页的离线生成链。建议后续整体迁移到单独的 `platform-tools/` 工程；本次暂不移动脚本，避免破坏现有操作记录。

## 清理原则

- `out/` 只保留四个正式交付页、主链需要的 JSON，以及审计脚本硬依赖的 `route_kuandeng_routes.html`。
- 带 `_` 前缀的调试物、截图和探查页面进入日期归档目录。
- `*.bak*`、`*_before*`、`*_v2/*_v3` 等历史快照先归档，不直接删除；确认无回滚需求后再清除。
- 凭据文件不属于产物，禁止提交或留在共享归档中，应改用环境变量/本机密钥存储。
