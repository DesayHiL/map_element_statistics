路线验收方案，三句话说清

一条点到点路线（起点 O → 途经点 → 终点 D）怎么跑、怎么判、为什么靠得住 · v0.1 · 2026-10-09
① 一条路线跑一个来回
单程路线只跑一遍（d=1）；往返来回各一遍（d=2），同一车次连续完成
② 路上查三类点
端点（致命）· 灯控锚（关键）· 段落点位（一般）
③ 毛病够少即合格
不合格点位 ≤ 8/40，且端点、锚点全过

端点 · 致命

起终点 / 途经点的可停靠、进出通道、掉头空间。

方式：100% 全检 · 现场静态确认，各 10 min，拍照留档。

为什么全查：数量少、一票否决——任一不过，整条路线不通过。

锚点 · 关键

路线走廊内全部灯控停止线 / 信号灯。

方式：100% 全检 · 用采集数据判读。

为什么全查：穷举得起的一律全检——漏检率为 0，不需要抽样论证。

段落 · 一般

标线线型 / 颜色、车道数 / 属性、限速等。

方式：每条路线抽 40 个点位判读 · 按路段长度分层随机。

为什么抽样：全查查不起——抽样就必须给出统计证明（第④屏）。

采集是全长的，抽样只在判读环节。按方向把整条路线跑完（里程覆盖 100%），回来后从采集数据里抽 40 个点位判读——不是"只跑抽中的路段"。
验收成立三要素（缺一即为摸底，不是验收）：判据有出处（阈值引 ODD 定义 / 要素规范 / 客户准则）· 抽样有证明（误判概率说得清）· 方案先冻结（开测前签字，期内不改）。

上承《川行无人车智驾验收测试标准》单路线交付验收流程（方法层增补，既有准出条款不动）；路线集全部完成路线验收后，才进入区域验收（开区准出）。统计口径与出处见技术底稿 docs/route_acceptance_plan.md。

什么时候跑

默认只用平峰：9:30–11:30 / 14:00–16:30。

ODD 含高峰 / 夜间 → 同一条路线加跑，里程与工时近似线性增加；夜间判读需人工复核。

排期顺序：先排窗口稀缺的（夜间 / 高峰）→ 平峰填空 → 天气敏感项最后。

采集按方向跑完整条 → 里程覆盖 100%；回来判读时才抽 40 个点位（第③屏）。

第③屏 · 怎么判

40 个点位里，毛病够少即合格

点下面的格子试试——把格子点成「不合格」，看判定怎么变（这就是判读员干的事）

试判台：40 点位

0 / 40 不合格点位
合格端点全过 + 锚点全过 + 不合格点位 0/40 ≤ 8。毛病够少，归档。

40 个点位怎么抽：按路段长度分层随机——长路段多抽几个、短路段少抽，不是纯随机撒点。

判定规则（单路线 verdict）

verdict条件动作
合格端点全过 且 锚点全过 且 不合格点位 ≤ 8/40归档
存疑（复测）不合格点位 9–12重抽 40 点位合并判读；合并后仍 > 8 → 不合格
不合格不合格点位 > 12，或端点 / 锚点任一 fail返工失败项（不是整条重跑），复验只补失败项

端点、锚点是全检项——不在 40 个格子里，单独成行；任一 fail 直接一票否决，点多少格子都没用（试试上面两个红色按钮）。

路线状态机：未跑 → 已跑 → 存疑 → 通过 / 返工中 → 不通过（第⑥屏）。

第④屏 · 为何是 40 个点、判 8

两个问题分开看：抽得准吗？判得对吗？

「抽得准」问 40 个点能不能代表整条路；「判得对」问判错的风险有多大。两件事都用数字回答，不用感觉

问题一 · 抽得准吗——误差带随点数收窄

误差带 ∝ 1/√点数：点数翻 4 倍，误差才减一半。想压到 ±5 要 139 个点——不划算。所以本方案不追求把误差带抽窄，而是用「判 8」控制两头风险（右图）。端点 / 锚点是全检，没有这个问题——漏检率为 0。

问题二 · 判得对吗——错判概率

抽 40 判 8：好路 98.4% 判过（冤枉率 1.6%）；差路只有 11.1% 蒙混（漏放率 11%）。
只抽 20 判 4：差路漏放 23.7%——每 4 条坏路线放过 1 条，只能当开测前的快速筛查，不能作验收依据。

隐形瓶颈是判读，不是车。

判读工时 ≈ 出车工时 × 1.5。判读人力不足时，加车无效——车越多，积压的判读越多。

排产先算判读人力，再定出车节奏。

三个里程口径分开记账：验收里程 = Σ(单程 × 方向数)；出车里程 ≈ 验收里程 × 1.3–1.4；复测里程小（返工只补失败项，不重跑全程）。

第⑥屏 · 判定规则

一条路线的状态机 + 一批路线的结论

不合格不是整条重跑——返工粒度是失败项，复验只补失败项

批次结论（本次全部 N 条路线）

结果批次结论
N / N 合格通过
(N−1) / N 合格有条件通过——不合格路线整改后复验
≤ (N−2) / N 合格不通过——必须排查系统性原因（数据源、判据、采集设备），不得只修单条

批次大小 N 开测前定死，判定规则随 N 固化。

返工粒度 = 失败项。

不合格不是整条路线重跑——只返工失败的端点 / 锚点 / 点位；复验也只补这些。所以复测里程小，不爆预算。
第⑦屏 · 有效性五证

怎么证明这套跑法靠得住

五张证据卡，每张都有「不成立的信号」——出现信号说明方案失效，须修订后重验
证 1

统计检出力

冤枉率 1.6%（好路被误判）、漏放率 11%（差路蒙混）——读数见第④屏。

信号：漏放率 > 20% → 方案过松，须加大样本
证 2

覆盖证明

端点 + 锚点 100% 全检；采集覆盖 100% 里程；抽检覆盖率 = 40 点位 × 段长 ÷ 路线总长，写入报告。

信号：给不出分子分母
证 3

可重复性

每批次抽 2 条路线二次采集，两次 verdict 一致率须 100%。

信号：出现不一致 → 判读判据有歧义，修订后重验
证 4

方案冻结

判据、抽样、判定规则开测前签字冻结；期内不更改，变更走变更记录。

信号：测试中调阈值 → 结论作废
证 5

可追溯

基线快照、原始采集数据、逐项判读记录、verdict 全部归档，第三方可复核。

信号：判读结论回溯不到原始数据
待确认

开测前必须闭环的 4 件事

① 判据阈值（唯一外部输入）：须引自 ODD 定义 / 要素规范 / 客户准则；未确认前可采集，不得出「合格」结论
② 方向（单程 / 往返）与时段窗口数——每加一个窗口，成本近似翻倍
③ 判读人力配置——判读 ≈ 出车 × 1.5，是隐形瓶颈
④ 批次大小 N——判定规则随 N 固化

每条路线归档四组字段——基线 / 采集 / 判读 / 结论（明细见技术底稿 §8）；缺项视为未完成验收。
